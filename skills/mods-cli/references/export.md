# Export resolved files and Profile State

Use `mods [--environment PATH] export OUTPUT [--include-saves] [--dry-run]` to create a folder of resolved ordinary files. `OUTPUT` is relative to the shell's startup working directory, not the Environment Root. The destination parent must exist; `OUTPUT` must not exist, even if empty. Choose a destination outside the Environment Root. Run `--dry-run` to inspect paths, providers, file counts and bytes without creating or reserving output. Rerun without it only after checking the destination and stopping programs that write the source. Normal success prints nothing.

```powershell
mods --environment 'D:\Mod Environments\Mojave' export 'D:\Exports\Mojave' --dry-run
# After reviewing the preview and approving the write:
mods --environment 'D:\Mod Environments\Mojave' export 'D:\Exports\Mojave'
```

The package has separate `Data/` and `profile/` directories. **Place files manually** at a compatible destination only after checking its game version, file conflicts and existing profile. Copy `Data/` contents beneath the destination game's `Data/`, not as a second nested `Data/`. Do not copy `profile/` wholesale into `Data/` or assume it maps to one runtime directory. Place game INIs (such as `Fallout.ini`, `FalloutPrefs.ini`, `FalloutCustom.ini`, `GECKCustom.ini`, and `GECKPrefs.ini`) in the destination's corresponding Documents/My Games profile, and `plugins.txt`, `loadorder.txt` and `Plugins.fnvviewsettings` in its corresponding Local AppData game profile. With `--include-saves`, place `profile/saves/` in the intended Documents/My Games save location after checking for existing saves. The exact paths depend on the destination's Windows or Proton prefix configuration; identify them first. `modlist.txt` records provenance and is not game activation state. Missing optional source files stay missing; the package does not fill them in.

Only enabled analytical Data winners, unique participating files and effective Overwrite files are selected. Steam-base files, disabled or losing providers and manager-private metadata are not exported. Ordinary mod-supplied plugins and INIs remain Data files. BSA files are opaque: export copies physical BSA bytes but does not inspect their members. The support `Data/Fallout - Invalidation.bsa` is an explicit generated exception, not a mod winner or bundled base asset. Exported INIs carry the matching invalidation settings; placing the BSA alone is insufficient. Check those INIs and the destination's own archive setup before launching. Export does not prove in-game invalidation.

Files retain source modification times, including derived profile INIs and the support BSA. This does not preserve ACLs, creation times or alternate streams. `loadorder.txt` and `plugins.txt` are copied as state, not recomputed or enforced by retiming plugins. The analytical load order is advisory. Export does not sort plugins, rewrite mod paths, install a mod manager, synchronize saves or change the destination automatically. Upstream usvfs mappings are not guaranteed to implement analytical Tombstone suppression at runtime; this export follows the analytical positive-file resolution rather than a capture of every runtime-visible file. A copied folder is not a guaranteed playable setup.

Source writers must be stopped before preview and export. Preview reserves nothing and does not ensure the later export sees identical sources. Export does not compare sources again while it copies, so a change made during export can appear in the output. Export creates the new destination folder and writes files into it directly. Failures or cancellation can leave partial files in the destination; stderr reports that folder as `retained_partial_output`. Inspect it before any manual cleanup or retry. Export does not roll back or delete partial state. No destination apply or game launch occurs.
