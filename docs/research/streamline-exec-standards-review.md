## Focused independent checks

- **Callable ports:** `dependencies/{explain_path,inspect_mod_conflicts,install_archive,set_game_directory,list_effective_conflicts}.rs` calls inherent factory methods to *construct* application port closures, not ports directly. `runner.rs` calls a presentation-owned composition callback. Application port invocations in changed application code remain explicit `.call((...))`; factory function-call syntax is allowed. No callable-port breach.
- **Error causes:** Windows `launch_inputs/windows_inputs.rs:108-116` deliberately discards candidate metadata errors only when no error is returned at that point: a non-NotFound candidate is selected and Windows process creation decides access/format. This is the approved policy; the subsequent launch error is preserved. Manifest concurrent-source refusal at `manifest_writer.rs:70-79` is a newly detected semantic conflict with no underlying I/O error to attach; the open/read paths do preserve their I/O reports. CLI moved-load failures go through `error::application_error(&report)` allowlisting, not raw formatting.
- **Guard clauses:** `execution_preparation/inventory.rs:121-145` uses `match` to distinguish successful metadata, absence/create/race, and actual errors; `:289-301` continues after directory recursion. `profile_state.rs` value selection and runner command dispatch have continuing alternative branches. No confirmed guard-clause breach.
- **Cancellation:** Changed application use-case signatures keep dependencies first and cancellation final where supported; the new infrastructure inventory signatures do likewise. `manifest_writer::replace_validated` has a validation callback *after* cancellation, but this is an infrastructure helper, not an application use-case signature; its final pre-rename check is inline and no check follows the final rename. No confirmed cancellation breach.
- **Composition:** `main.rs` creates resources after CLI parse/root selection, bypasses settings for init, loads a command snapshot once, then supplies narrow bindings/snapshot to command-local closures. `Resources::system` does not load settings. Binding captured immutably inside infrastructure closures is explicitly permitted and is not a global context bag. Strict export integrity rereads are source validation, not configuration rediscovery.

- Possible **Middle Man**: `Resources::load_settings` forwards to `SettingsAdapter::load_command`, but gives the CLI composition root one narrow capability while keeping the adapter private. No action recommended.
