# JSON output

Use `mods --json COMMAND` to request one final JSON document. The flag is global and explicit. Redirection and piping do not turn it on. Pass child arguments after `exec --`; a child `--json` is not a CLI flag. Success goes to stdout. An ordinary failure goes to stderr. JSON mode does not ask for input or grant approval.

The [schema](schema.json) and [examples](examples) define the public shape. Validate a document against the schema definition for its command. The aggregate schema uses `anyOf` because successful mutations permit additive fields. Each command has its own top-level result. Every success has `warnings`, an ordered array of `{code, message, details}` objects. Quiet mutations, including `shortcut`, return `{"warnings":[]}`. A successful `shortcut` hides the `diagnostic_logging_unavailable` warning in text mode, but JSON keeps it in `warnings`. `config list` returns `settings`, while `config get` returns `setting`. Settings expose `key`, `value`, `source`, `manifest_value`, `manifest_path`, `shadowed`, and `writable`. Unset values are `null`. A source has a `kind` and, when relevant, `variable` or `argument`.

`conflicts list`, `inspect`, and `explain` return File Conflict results, including `resolution_status`, ordered providers and rows, comparison states, and `problems`. Exit zero can still include problems. `install` returns `outcome` with one of `additional_selections_required`, `preview`, or `installed`. A required-choice response includes accepted choices and unresolved groups. Resubmit the full choice set on the next invocation. A preview includes the Install Plan and hypothetical enabled File Conflicts. `plan.projected_state.mode` is `new_install`, `replacement`, or `unlisted_replacement`; the last means `--replace` takes over an entry in `mods` that `modlist.txt` does not list. An installed response acknowledges completion. Exit zero alone does not establish completion. A Nexus mod-page input that needs a file choice fails with the `nexus_file_selection_required` Problem, exit code 2, and `details.files`: every available file in published order, each with `file_id`, `name`, `version`, and `category`. Rerun with `--file ID`. Every provider object has the same shape in conflict and installation results: `kind`, `priority`, `original_path`, `participation_reason`, and `mod_name` for a Data Mod. `priority` is an object whose `kind` is `base`, `regular` (with an integer `priority`), or `overwrite`.

`export` returns `outcome` `preview` (with `--dry-run`) or `published`, the requested `output` folder, `total_bytes`, and `files`. Each file has a `path` relative to the output folder that starts with `Data\` or `profile\` (saves from `--include-saves` are under `profile\saves\`), `bytes`, and a `provider`. A provider `kind` is `steam_data`, `data_mod`, or `overwrite` with the same `priority` object as other providers, or `profile` or `generated_invalidation`. Without `--dry-run`, `files` lists what was written. `warnings` holds the plugin warnings that `exec` also prints: `stale_plugin_entry` with `details.plugin`, and `duplicate_plugin_entry` with `details.plugin` and `details.file` (`plugins.txt`). A failed export is a Problem. Its `details` can name the requested `output`, the `retained_partial_output` folder, the `retained_export_stage`, and `output_complete` when only the stage removal failed.

`--json --help` returns `{ "help": "...", "warnings": [] }`. `--json --version` returns `{ "version": "...", "warnings": [] }`. Help text is human-readable, not a command catalogue.

Errors use [CLI Problem Details](problems.md): `type` is a permanent repository Markdown link and the primary machine identifier; `title` is a stable label; `detail` describes this occurrence. `code` repeats the type identifier, and `exit_code` gives the process result. `details` contains only the allowlisted fields listed in [problem details](problems.md#details), such as `phase`, `field`, `mod_name`, `files`, `load_order_file`, and retained paths. `instance` is present only when a Diagnostic Session identifier exists. Warnings may appear on a failure. There is no HTTP `status` field. Raw internal error chains are not public output.

`exec` is the exception. The launched child writes live, binary-safe stdout and stderr to the same respective streams in both modes. It inherits stdin. The CLI adds no success document. A nonzero child exit remains the child's exit code and does not become Problem Details. Before launch, CLI failures are JSON Problem Details. A failure to set load-order times has `phase` `load_order` and `details.load_order_file`. A failure after the profile INIs were staged has `details.retained_execution_inis`. Once launched, warnings and supervision or cleanup failures are plain stderr; a supervision or cleanup failure exits nonzero. No post-launch JSON document is mixed with child output. `exec --hidden` (Windows only) captures child output privately instead of forwarding it and reports failures in a dialog. `--json` with `--hidden` is rejected as `invalid_arguments` (exit code 2) before the console is detached. A Launch Shortcut stores `exec --hidden` without `--json`, even when it was created with `mods --json shortcut`, so a launch from a shortcut never emits JSON.

Before 1.0.0, the JSON format may change in any release. The compatibility rules below start at 1.0.0. From 1.0.0, the JSON contract follows the product version. Breaking changes need a major version bump. Additive fields, warning codes, and problem types may appear without one. Consumers must ignore unknown additions. Removed fields, changed types or meanings, and new values for closed enums such as `outcome` are breaking changes. Human-readable wording is not stable API. There is no separate schema-version field.

## Validation limits

The CLI unit tests cover JSON publication and pre-launch versus post-launch error routing on macOS. Native Windows child stdout/stderr byte forwarding, inherited stdin, and actual child exit status need a Windows runtime run. Hidden execution (console detachment, private capture, and the failure dialog) also needs a Windows run. Those checks are blocked on macOS, not passed.
